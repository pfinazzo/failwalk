# Acceptance criteria

Task: failwalk v1, the map: `failwalk ui` draws the grid as a 3D picture in one self-contained HTML file. Base branch for the diff: `main`.
Frozen with `claimcheck spec freeze`. Add nothing after the diff starts.

- [ ] 1. `failwalk ui` reads `failwalk-inventory.json` (`--inventory`, required), `failwalk-trace.json` (`--trace`, used when present) and `failwalk.json` (`--report`, used when present), writes one HTML file (`--out`, default `failwalk-ui.html`) and opens it with the platform's opener (`open` on macOS, `xdg-open` on Linux, `start` on Windows) unless `--no-open` is given. A missing inventory file throws an error naming the path and saying to run `failwalk inventory` first.
- [ ] 2. The HTML file needs nothing else on disk: the data is inside it, the styles and the script are inside it, and Three.js is loaded from a CDN at one pinned version through an import map. The theme is dark. The camera orbits on drag, pans on right-drag or shift-drag, and zooms on scroll.
- [ ] 3. The data shaping is one pure function, `shapeScene` in `src/ui/shape.ts`, from the inventory, the trace or null, and the report or null, to the scene data: `modes` (the report's plan modes when there is a report, else every mode in grid order), `wrappers` (one per wrapper name in inventory order, each with its site ids), `sites` (one per inventory record in inventory order, with its file, line, wrapper, method, kind, checks, the labels of the tests that reach it, and one cell per mode), `tests` (one per trace test that reached at least one site, with its label, file, name and site ids), `status` (`inventory-only`, `traced` or `run`) and `notice` (one sentence saying what to run next, empty when the run is complete).
- [ ] 4. Each cell has a `verdict` and a `state`, looked up from one table: `PASS` and `FAIL` give `coped` (green); `CRASH` and `HANG` give `uncaught` (red); `RISK` gives `risk` (amber); `UNREACHED` gives `unreached` (grey); a site that no test reaches, or a site whose cell has no verdict yet because there is no report, gives `unreached` (grey). No state is chosen by an `if`/`else` ladder.
- [ ] 5. Each cell carries a `note` in plain words: the verdict, how many times the injection fired, the checks behind a `RISK`, and the first line of the first failure message; for a grey cell, why it is grey.
- [ ] 6. The picture: each wrapper is a group of call-site nodes, each node placed by its file, each test that reaches a node is a beam from the test to the node, and each site shows one row of cells, one per mode, coloured by its state. A legend names the four colours.
- [ ] 7. Clicking a call-site node opens a panel with the file and line, the wrapper method called, the kind, the checks that fired, the tests that reach it, and one line per mode with its verdict and note. Clicking a test node lists the sites it reaches. Clicking a wrapper group lists its sites with their worst state.
- [ ] 8. A greeting asks whether to walk through everything or explore. The walkthrough shows the big picture, then each wrapper, then each uncovered cell (red, amber, then each grey site), with Back and Next, the arrow keys, a chapter menu, a progress bar and Exit; the first step has no Back and the last has no Next; clicking anything mid-walkthrough pauses it and offers to return to the same step. Explore shows the whole scene with the panel on click.
- [ ] 9. On `examples/sample-api` after `failwalk inventory`, `failwalk trace` and `failwalk run`, the page shows every cell with its real verdict. On a folder with an inventory but no trace, every cell is grey and the page shows the notice sentence. The page opened in a headless Chromium logs no console error in either case.
- [ ] 10. A unit test covers `shapeScene`: the modes, the wrappers, the site rows, the test beams, every state in the lookup, the three statuses and their notices. `npm test` exits 0.
- [ ] 11. The README gains a "The map" section with the command, a screenshot under `docs/`, and what each colour means.
- [ ] 12. `docs/decisions.md` records why the map is one self-contained HTML file and why rows are call sites and columns are failure modes.
- [ ] 13. Nothing in failwalk names, reads or depends on any real-world service or repository, and all new source follows the conventions in `~/.claude/CLAUDE.md`: arrow-function consts, one named-params object per function, lookup tables instead of branch chains, a doc block on every function, no classes, no mutation of inputs, no `await` inside a loop over a collection.
